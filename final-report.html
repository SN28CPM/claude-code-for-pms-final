What happened, plainly

4.2 cut the ping wait from 90 to 60 seconds. Responders who need a little over a minute now "miss" pings, and the routing code punishes a miss exactly like a "no", with no recovery over time.

It wasn't an "August dip". Turn-downs didn't rise, the drop starts on release day, and work moved from four people to ten others instead of falling for everyone.

A 2019 note in the code asked whether scores should recover over time. Nobody came back to it, so the shorter wait turned a small rule into a trap.

Module 5 · Super Speed · the fix

Keep 60 seconds, change what happens around it.

My prompt, exactly as typedCan you create a solution brief to fix the issue while keeping the 60s response time?

Artifact: 05-super-speed/brief.md. The ping stays open after 60 seconds (the first yes wins), being late is no longer a "no", and every score gets one fresh start. Stress-tested on 20 runs: no fix works without the fresh start, not even going back to 90 seconds.

Slow responders' pings a week, by fix (test data)

Median of 20 runs; slow responders made 14.3 pings a week under 4.1. If they really answer in 100s, "back to 90s" collapses to 1.1 a week; this proposal holds at 14.4.
